# 热量系统

模组里所有"热量"都遵循同一条设计原则：**双向叠加 + 速度效率**。

> 球加热生物的同时自己也被加热；而这一切都按"当前速度 ÷ 0 级蓄力出手速度"折算 ——
> **停住的球不产生热量**。

---

## 一、三条热量链

| 谁 | 热量存在哪 | 谁在加热它 |
|---|---|---|
| **球自身** | `BallProjectile.heat`（内部字段，**不进存档、不同步客户端**） | 范围内的金属方块 + 范围内生物的金属装备 |
| **生物** | 数据附件 `more_balls:prospecting_heat`（会存档） | 范围内球的金属装备数 |
| **方块** | `ProspectingHeatData`（**维度级**存档） | 范围内球的「1 + 紧邻矿物数」 |

三者**每刻各自结算**，互不等待。

---

## 二、作用范围

| 参数 | 值 | 说明 |
|---|---|---|
| 生效半径 | **7 格** | 热量结算、烤矿、磁吸转向都只认这个范围内的目标 |
| 扫描间隔 | **8 刻** | 每 8 刻重新扫一次范围内的方块与实体 |
| 磁吸半径 | 2.5 格 | 【磁性】单独的偏转范围，与热量无关 |

范围判定用**球心到目标中心的直线距离**，不是包围盒。

---

## 三、核心公式：效率系数

**一切热量增长都要乘以这个系数。**

```
heatEfficiency() = 当前速度 ÷ 基准速度

基准速度 = 该球的配置初速度 × 0.15
```

- **停住的球效率 = 0** —— 所以静止的球不会凭空积热，也不会继续烤东西
- **飞得越快积得越快**
- 基准取的是**0 级蓄力出手速度**，所以蓄力射出的球效率可以超过 1.0（相当于更快积热）
- 不同球各有各的基准（雪球类慢、铁球快），都按自己的初速度折算

> ⚠️ 实现细节：`getDeltaMovement()` 是**物理量纲**，而球的 `velocity` 配置是**配置量纲**，
> 二者差一个固定倍数 `0.15`。搞错这个比值会让整体积热速度缩水 6.7 倍。

---

## 四、球自身的热量

```
每刻增量 = ( 附近金属方块格数 + Σ 范围内生物的金属装备件数 ) × 效率
```

### 两个来源

**① 金属方块**（`nearbyMetalBlocks`）

扫描半径内所有"能吸热的金属类方块"的**格数**。判据是方块能不能熔炼出金属产物，
**包含金属储存块**（铁块、铜块这类也算；它们会冒火、会烫脚，但不会被烤坏）。

**② 生物的金属装备**（`heatFromEntities`）

范围内每个生物身上**带金属词的装备件数**，逐个相加：

```java
for (LivingEntity nearby : 附近生物) {
    heatFromEntities += countMetalEquipment(nearby);
}
```

**金属词表**（按物品注册名子串匹配）：

```
iron  chain  gold  golden  copper  steel  bronze
netherite  silver  tin  lead  aluminum  aluminium  titanium  zinc
```

> ⚠️ **`diamond` 不在表里** —— 穿钻石甲的对手**完全不提供热量**。
> 皮革甲同理。

**投掷者本人的装备计入**（2026-10-09 起）—— 他身上的金属装备会让球按**正常效率**积热，
所以自己扔出去的球，起飞那一段就能蹭到自己的一身甲，不必先飞到别人身边。

但**他本人不会被这颗球加热** —— 生物侧那条链仍然排除掷出者（见下面「生物的热量」）。

### 重要特性：球的热量**只增不减**

球自身的 `heat` 字段**没有任何衰减逻辑**，只有两种变化：

```java
this.heat += totalGain * heatEfficiency();   // 涨
this.heat = 0;                                // 只有【引雷】触发时清零
```

所以：

- 球一旦在矿脉附近飞过、攒够了热，**落地停下后热量不会散掉**
- 停住的球**不会再涨**（效率为 0），但已有的热量**原样保留**
- 【熔融】【引雷】的阈值判定用的是这个**累积值**，与"当前是否在飞行"无关

### 触发点

| 词条 | 条件 | 结果 |
|---|---|---|
| **【融化 x】** | `heat ≥ x` | 球自己化掉（消失） |
| **【引雷 x】** | `heat ≥ x` | 热量**清零** + 释放 4–9 道闪电，球本身留着 |
| **【熔融 x】** | `heat ≥ x` **且命中生物** | 给目标挂上「熔融物烧伤」，球不消失 |

【融化】和【引雷】在**每刻**判定；【熔融】在**命中时**判定。

## 五、生物的热量

```
每刻增量 = 该生物身上的金属装备件数 × 效率
```

- **没穿金属装备的生物完全不参与**（`metal <= 0` 直接跳过）
- 使用者本人不吃这套（球的主人不会被自己的球烤）

### 阈值与表现

| 阈值 | 值 | 表现 |
|---|---|---|
| 着火 | **> 100** | 每刻续燃 20 刻（1 秒）的火焰 |
| 上限 | **200** | 封顶 |
| 熔融物烧伤 | **= 200 且穿着金属盔甲** | 持续挂「熔融物烧伤」 |

### 降温

| 情况 | 每刻降温 |
|---|---|
| 常态 | **0.2** |
| 泡在水里 / 淋雨 | **2.0**（×10） |

**刚被加热过的 1 刻内不降温** —— 避免"边加热边衰减"互相抵消。

---

## 六、方块的热量

```
每格每刻增量 = ( 1 + 该格紧邻六面的金属矿物数 ) × 效率
```

**矿脉越密的地方被烤得越快** —— 一格周围围着 6 格矿就是 7 倍速。

### 阈值

| 类型 | 阈值 | 结果 |
|---|---|---|
| 可破坏的金属矿 / 粗矿 | **200** | **烤熟破坏**，掉对应金属产物 |
| 粗矿块 | **200 × 8 = 1600** | 同上（粗矿块更难烤） |
| 其它金属块 | **200 封顶** | 冒火、踩上去烫脚，**方块本身永远不破坏** |

### 降温与结算

| 参数 | 值 |
|---|---|
| 方块降温 | **0.2 / 刻** |
| 结算间隔 | 每 **5 刻** 一次 |

**降温与爆破在世界 tick 里做** —— 球飞走之后余热仍然会继续散、攒够了照样炸开。

### 烫脚

热量超过 **50** 的方块会像岩浆块一样对踩上去的生物造成伤害，
伤害类型沿用原版的 `hotFloor`（所以死亡提示、抗性、附魔都跟着原版走）。

### 冒火

热量超过 **50** 开始冒火焰粒子。粒子按**绝对热量**判定，不是按阈值的百分比。

## 八、积热速度的实测参考

对战环境（无矿脉）下算一笔账：

```
对手一身铁甲 + 铁武器                      ≈ 6 件金属装备
掷出者自己的一身甲（2026-10-09 起也计入）   ≈ 4~6 件
合计 ≈ 10~12 件

球飞 1.5 秒（30 刻），平均效率按 0.6 估：
30 × 10 × 0.6 ≈ 180 点热量
```

而两个阈值现在是 **120** —— **对战里能攒满**，不必先去找矿脉。
这也正是把阈值一路从 300 / 200 降到 120 的原因
（另加「掷出者自己的甲也算热源」这条改动，见上文）。

> 这是估算，实际值受球速、距离、双方装备数影响。
> **裸装对裸装**（双方都没穿金属）时仍然攒不起来 —— 那时一个热源都没有。
