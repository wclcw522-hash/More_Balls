## 三、图标是怎么做的

**绝大多数图标直接借用原版物品**（铁块、钻石块、末地烛、僵尸头……），不用额外资源。

**两个图标有讲究**：

| 成就 | 图标 | 做法 |
|---|---|---|
| 排列组合 | 组合球 | **本模组的物品 + 数据组件**（`more_balls:combo_sources`），所以图标本身会显示一组具体材质 |
| 三军听令！ | 三颗雪球 | **拼合模型**：`assets/more_balls/items/advancement/three_snowballs.json`，用 `minecraft:composite` 把三个原版雪球按不同位移缩放摆成三角，**不需要贴图** |

> ⚠️ **拼合模型的位移不能顶出物品格子**。物品图标的可视区大约是 1×1 格（±0.5），
> 单个部件「位移 + 缩放一半」的绝对值要小于 0.5，否则成就界面里只能看到边角。
> 参考原版 33 个用 `composite` 的物品图标：位移都在 0～0.5，缩放 0.667～1.0。

## 四、触发方式

成就用的是两种驱动方式：

| 方式 | 用在哪些 | 说明 |
|---|---|---|
| **数据驱动**（纯 json） | `root` / `rubble` / `iron_ball_from_blocks` / `fufu` / `combo_ball` | 用 `minecraft:inventory_changed` 或 `minecraft:recipe_crafted`，**不用写 Java** |
| **Java 手动发放** | 其余 | json 里写 `minecraft:impossible`（永不自动触发），由模组在合适的时机调 `ModAdvancements.award(player, ID)` |

**所以想改「什么时候给成就」，先看它在上面哪一栏**：
数据驱动的改 `data/more_balls/advancement/<id>.json` 里的 `criteria`；
Java 发放的要去 `ModAdvancements` 里找对应常量、再去调用点改逻辑。
